# 投研报告 Web 端浏览页面 — 设计文档

日期：2026-07-18
状态：已确认

## 背景与目标

reports/ 目录现有约 2128 篇 Markdown 报告、200+ 个一级条目（公司目录、散落的主题报告、CSV 筛选结果混杂），直接翻文件浏览困难。

目标：本地起一个 Web 服务，解决三个痛点——**找报告（标题检索）、阅读体验、汇总仪表盘**。

关键约束：
- 仅本地使用，不部署、不认证
- **不改动任何报告文件**，元数据全部从文件名/路径/内容自动推断
- 无构建步骤，新报告刷新即见
- 不写测试，实现后人工验证

## 整体方案

本地动态服务（Flask）+ 单页前端（vanilla JS），文档站式布局：左侧公司树导航 + 右侧阅读区，顶部标题搜索，仪表盘为次级页面。

```
web/
├── server.py         — Flask 服务，实时扫描 reports/（约 200 行）
└── static/
    ├── index.html    — 单页应用
    ├── app.js        — 前端逻辑
    ├── marked.min.js — Markdown 渲染库（本地 vendor，离线可用）
    └── style.css
```

启动：`python web/server.py`，访问 `http://localhost:8600`。

## API 设计（3 个接口）

| 接口 | 说明 |
|------|------|
| `GET /api/index` | 扫描 reports/ 返回全部报告索引：标题、公司、类型、日期、路径、分组。目录 mtime 缓存，变化时重扫 |
| `GET /api/report?path=` | 返回指定报告原始 Markdown。路径必须解析后位于 reports/ 内（防目录穿越） |
| `GET /api/dashboard` | 最近报告流（按日期倒序 Top 30）、持仓公司卡片（解析 portfolio-latest.md 持仓表）、覆盖统计（按公司/类型/月份计数） |

搜索仅覆盖标题/文件名，`/api/index` 已含全部标题，由前端过滤实现，无独立搜索接口。

## 元数据推断规则

| 字段 | 规则 |
|------|------|
| 公司 | 一级目录名（`reports/腾讯/…` → 腾讯）；根目录散文件取文件名首段；含 vs/对比 的归入「主题/对比」 |
| 类型 | 文件名关键词映射：research / earnings / thesis / checklist / industry / funnel / private / team / management / 公众号 / 其他 |
| 日期 | 文件名中 `YYYYMMDD` 或期间（如 `2025Q4`）；缺失则用文件 mtime |
| 标题 | 报告第一个 `# H1`，回退到文件名 |
| 分组 | 持仓公司（置顶，来自 portfolio-latest.md）→ 公司（按报告数排序）→ 行业研究 → 主题/对比/漏斗 → 公众号文章 → 其他 |

非 md 文件（CSV 等）不进索引。portfolio-latest.md 解析失败时持仓分组为空，不报错。

## 前端页面

### 侧栏 + 阅读区（主视图）
- 左侧树形导航按上述分组展开/折叠，每个公司节点显示报告数
- 顶部搜索框：输入即过滤（匹配标题、公司名、文件名）
- 阅读区：marked 渲染，表格加边框和斑马纹（报告表格密集）、引用块样式化（大师语录）、★ 评分原样保留
- 右侧浮动 TOC（H2/H3 自动生成，点击跳转）
- 报告内相对链接跳转（系列文章 01→02）、图片正常加载
- 阅读页展示同公司其他报告列表（按日期倒序，形成研究时间线）

### 仪表盘（次级页面）
- 最近报告流：按日期倒序
- 持仓公司卡片：持仓名称、占比，点击进入该公司报告列表
- 研究覆盖统计：报告数按公司 Top 20 / 按类型 / 按月份的简单计数条

## 明确不做（YAGNI）

- 全文搜索（仅标题级）
- 编辑、认证、部署
- 修改报告文件、批量加 frontmatter
- 构建步骤、前端框架、打包工具
- 自动化测试

## 验证方式

实现后人工验证：索引数量与 `find reports -name "*.md" | wc -l` 一致；抽查腾讯（多报告公司）、系列子目录（《看懂智元机器人》）、根目录散文件三类的分组与渲染；仪表盘持仓与 portfolio-latest.md 一致。
